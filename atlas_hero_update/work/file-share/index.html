Architecture & threat callouts

Flow matches the coursework design: upload → object store → notify function → mail → HMAC token link → verify → short-lived download → expiry / auto-delete. Callouts cite mitigations from the real application logic (injectable clients, HMAC tokens, conditional notification claim, download_status map, grace-period delete).

1 · Spoofing

Forged download URLs

Mitigation: HMAC-SHA256 over base64url payload; verification rejects unsigned or wrong-key tokens before any object access.

2 · Tampering

Altered token bytes

Mitigation: signature checked with hmac.compare_digest (constant-time). Flipping a character fails verification; see token lab.

3 · Information disclosure

Direct object exposure

Mitigation: private bucket; recipients never get a permanent object URL — Flask exchanges a valid token for a short-lived presigned GET at click time.

4 · Denial of service

Huge uploads / fan-out

Mitigation: 25 MB content length cap, at most five recipients per upload, and email uniqueness when parsing the recipient list.

5 · Repudiation

“I never got / used the link”

Mitigation: per-recipient download_status map in DynamoDB; notify path claims queued → sending with a conditional update so duplicate events do not double-send.

6 · Elevation of privilege

Using someone else’s link / racing delete

Mitigation: token binds object key + recipient email; email must appear in the record; delete uses conditional upload_status <> deleted after every recipient is true (plus a grace timer outside tests).

Payload format matches the coursework: object_key + "\\n" + email + "\\n" + issued_at, then base64url(payload) + "." + base64url(HMAC-SHA256(secret, payload_b64)). Expiry is derived from issued_at inside the signed payload plus a max-age window — changing the clock without re-signing demonstrates age denial; rewriting issued_at in the token without a valid MAC fails as tampering.

What I built (sanitized)

  • Flask web app: course-demo login, upload form, tracked /download/<token> route.
  • Private object storage for uploads; metadata and per-recipient download flags in a NoSQL table.
  • Object-created notify function that mints one HMAC token per recipient and sends mail.
  • Shared stdlib HMAC token create/verify (no extra Lambda dependency package).
  • Click-time short-lived download URL after successful verify; auto-delete when every recipient has downloaded (extra credit), with a grace period outside automated tests.
  • Unit tests with fake cloud clients (no live account, no real email).
  • Least-privilege IAM policy templates for the compute roles (not root credentials for the app).
